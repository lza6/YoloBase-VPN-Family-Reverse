# YoloBase 框架深度逆向分析

对象：`com.yolo.networklibrary` + `com.yolo.base`（8 家白标 VPN 共用的商业框架）
样本：Eto Net Proxy 4.3.7（主样本，jadx 全反编译）+ 7 家分诊交叉验证

## 一、框架总览

YoloBase 是一套**白标 VPN 整体解决方案**（商业化产品）：
App 层只做 UI，节点下发/计费/广告风控全部走统一后端协议。
八家 App 的差异仅在：包名、品牌资源、`http_yolo_config.json` 三元组、资产 PNG。

```
com.yolo.networklibrary    HTTP 层：加密、签名、重试、Gson 序列化
com.yolo.base              App 框架：auth/permission/adlimit/install attribution
com.yoadx.yoadx            广告聚合 SDK
com.github.shadowsocks     shadowsocks-android fork（libsslocal.so = shadowsocks-rust）
```

## 二、配置三元组（一切密钥的源头）

`assets/http_yolo_config.json`（明文）：

```json
{
  "http_business": {
    "assetsResXTokenName": "eto.png",     ← AES key 派生材料（资产 PNG）
    "headerXToken": "",                   ← x-token 头（business 通常空）
    "hmacMd5Key": "aqOpd5a7WdcA6yWk",     ← Authorization 签名密钥
    "hostUrl": "https://eto.zoartechnology.net"
  },
  "http_common": {
    "assetsResXTokenName": "api_yolobase_net.png",
    "headerXToken": "xDk}g>Z#~:!b12B",    ← 公共通道固定 x-token（全家族共用）
    "hmacMd5Key": "",
    "hostUrl": "https://eto.zoartechnology.net"
  }
}
```

双通道设计：`http_business`（/cfg/* /login/* 节点与用户业务）与 `http_common`
（/hi /first_open 心跳与风控）各自独立 key/hmac/token。

## 三、密钥派生算法（LSB 位压缩，全链路最妙的一环）

`RepositoryCipherManager.createCipherKey()`：

```java
for (i = 0; i < len - (len % 4); i += 4) {
    bits = (b[i]&1, b[i+1]&1, b[i+2]&1, b[i+3]&1);   // 每 4 字节抽 4 个 LSB
    hex = Integer.parseInt(bits, 2) → format("%x");  // 4bit → 1 hex char
}
key = MD5(hexString).getBytes(UTF8);                  // 919 chars → MD5 → 32B
```

要点：
- PNG 本体被当**密钥容器**——3677 字节图片提供 919 bit 熵（不足，但服务端同 derivation
  所以可行）；
- 尾部 `len % 4` 字节直接丢弃；
- 输出 hex 串再 MD5，**32 个 ASCII 字符**就是 AES-256 key（不是 hex decode！第一次踩坑点）；
- Python 复刻见 `tools/yoloclient.py::derive_key`。

## 四、请求/响应全链路

### 请求

```
body     = Gson( BasePostRequest )           # ts/did/pkg/cv/mcc/mnc/gaid/utm_*/is_rooted/...
IV       = RandomStringUtils.randomAlphanumeric(16)
cipher   = AES-CBC/PKCS5(key, IV)            # javax.crypto 标准，无魔改
body_b64 = Base64.encode(cipher)

Headers:
  X-Yolo-Auth:    IV                        # 明文 IV 直接放头里
  Authorization:  HmacMD5(body_b64, hmacMd5Key).hex()   # 对 b64 串签名
  x-token:        headerXToken
  Content-Type:   application/json
```

`BaseRequest` 字段全表（服务端分流依据）：
`fb_install_referrer, ts, install_source, did, cnl, gaid, pcnl, utm_source/content/
medium/medium_name/campaign/campaign_name/creative_id/creative_name/country,
mcc, mnc, pkg, lang, cv, uid, token, is_rooted, is_vpn_used, phone_brand,
phone_model, os_ver, os`。
`BasePostRequest` 追加 `is_dev_mode / is_emulator / moon(磁盘剩余GB)`。
——**did 是设备指纹主键**：`/hi` 对同一固定 did 返回 `Banned Account`，
服务端有 did 黑名单。

### 响应

```
若 X-Yolo-Auth 头非空：
    IV2 = 响应头值（16 hex，服务端随机；与请求 IV 无关）
    plain = AES-CBC-Dec(key, IV2, Base64.decode(body))
否则 plain = body 原文
JSON = {error: int, msg: string, data: {...}}
```

错误码：`0=OK`，`9=Banned Account`，`10=Invalid Pkg`，`5/6/9/72=用户态通知`，
`-11/-13/-14/-15/-17/-18=客户端网络层`。

## 五、节点下发与 SS 内核

`/cfg/{newuser,olduser,lowuser,vip}` → `ServerResponse`：

```json
{"server_list": [{"group_id":"ca","iso_code":"CA","desc":"Canada",
  "servers": [Profile]}],
 "show_ad": true, "reconnect_time": 60, "disconnect_time": 86400,
 "special_mcc":["460","461"], "special_region":["CN"]}
```

`Profile` 即 shadowsocks-android 数据库模型直传：
`server/server_port/password/method/mode/is_auto/is_vip/weight/ss_type`。
客户端拿第一个 server 做自动重连（`CfgServerManager.AnonymousClass2` 计时器循环）。

SS 内核：`libsslocal.so` = shadowsocks-rust（字符串表证实 `aead_2022.rs`、
`ss-subkey` hkdf、AEAD2022_BLAKE3 支持）。启动参数 `--stat-path -c config --vpn --acl`。
配置由 `Profile.toJson()` 生成标准 JSON，**无插件、无魔改**——所以标准 xray/sing-box
理论上可直接握手（失败纯因服务端下线）。

## 六、风控与分流

- `UserLimitHandler.getCfgUrlByAdLimit()`：按广告限额状态选 `/cfg/newuser` 或 `/cfg/olduser`
  ——新用户看广告多，给不同节点池。
- `UserAttributesManager`：`isForbiddenRegion / isLimitRegion / isNotGpInstall /
  isOldUser` 四类风控标签，由 `/prod/api/first_open/` 与 `common` 通道下发。
- `special_mcc/region/language`：响应里下发特殊地区名单，客户端据此切广告策略。

## 七、八家交叉验证

| 通道三元组 | 差异点 |
|---|---|
| hostUrl | 8 家 8 个独立域（都挂 GCP GLB） |
| hmacMd5Key | 8 家 8 个（Stream/Rocket 同 key 同后端，双域部署） |
| 资产 PNG | 6 家独立 PNG；Lemon/Stream/Rocket 共名 `zz.png` 但**字节不同**（各自 key 不同） |
| headerXToken(business) | 全部为空 |
| headerXToken(common) | 全部 `xDk}g>Z#~:!b12B` |

结论：同一套框架 license 给 8 家运营，`zz.png` 是模板文件名但内容按家替换。
密钥分发 = 发 APK 时塞一张 PNG。

## 八、可复用产物

- `tools/yoloclient.py`：密钥推导 + 双通道 + 重放 + 收割，~150 行，零依赖除
  cryptography/requests。
- 新家入族只需：`http_yolo_config.json` 三元组 + 对应 PNG + 真实包名。
- demo `/api/reharvest` 已把 8 家全部参数化。
