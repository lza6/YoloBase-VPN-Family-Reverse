# 方法论与复用 — 本批新增的实战规则

沉淀自 VPN-Batch2（31 Mod APK 批量逆向）。通则已在 `apk-vpn-node-harvest` skill，
这里只记**本批新踩的**。

## 新规则

### 1. 资产 PNG 当密钥容器（LSB 位压缩派生）

白标框架爱把 AES key 藏在 assets 图片里，但不是整文件 hash——是**每 4 字节抽
LSB 拼 4bit 转 hex** 再 MD5。识别特征：
- `Cipher.getInstance("AES/CBC/PKCS5PADDING")` + `assets/*.png` + `MD5` 同类出现
- key 派生函数形参是 `byte[] rawByteArray` 且循环步长 4

解法模板见 `tools/yoloclient.py::lsb_hex_string + derive_key`。**注意 32 hex 字符
是 ASCII key 不是 hex-decode 后的 16 字节。**

### 2. 响应 IV 与请求 IV 独立

X-Yolo-Auth 头：请求时放客户端随机 IV，响应时服务端放**自己的**随机 IV。
第一次联调最容易卡在「拿请求 IV 解响应」——失败后先检查两头 IV 是否相等。

### 3. GLB anycast 假活

Google Cloud GLB（34.x.x.x 段）会对任意端口回 SYN-ACK——TCP 探测「全通」不代表
后端活着。判定链条必须是：TCP → **协议级握手**（真 payload）→ 业务目标请求。
`connect OK (0-2ms)` 且深探测 silent-drop = GLB 背后无人。

### 4. check-host.net 结果解析

`check-result` 的 value 形态：成功 `[{"address":..., "time": 0.009}]`，
失败 `[{"error": "..."}]`。判定 `v[0]` 是 dict 且有 `time` 键。
对照组必跑（google.com:443），否则分不清是检测器坏了还是节点死了。

### 5. 本机杀进程保护系统代理

v2rayN 的核心是 `xray.exe`（监听 10808）。批量测试后清理：
```powershell
Get-Process xray | Where-Object { $_.Id -ne <10808的PID> } | Stop-Process -Force
```
先用 `netstat -ano | findstr :10808` 拿守护进程 PID，`taskkill /IM xray.exe` 会连它一起杀。

### 6. did 是设备指纹主键

YoloBase 类后端用 `did` 字段做黑名单——同一个 did 反复请求 `/hi` 会拿 `Banned Account`，
但 `/cfg/*` 业务端点不受影响。收割脚本固定 did 即可，无需每次轮换。

### 7. 模板文件名 ≠ 模板文件内容

多家白标共用 `zz.png` 文件名，但每家字节不同 → 每家 key 不同。
**key 派生材料必须从对应 APK 里原样提取，不能跨家复用同名文件。**

### 8. jadx 内存控制

大 APK（60MB+）默认堆会 OOM：`JAVA_OPTS="-Xmx3g" jadx -j 4 --no-res --no-debug-info`。
dex 字符串挖掘优先用纯 Python `dexdump.py`（330MB 转储 / 43 APK / 3 分钟），
jadx 只在需要读方法体时上。

## 批量分诊评分模型（triage.py）

score = 50 + min(明文 scheme 链接数,20) + 15(标准内核) + 8(OpenVPN/IKEv2)
      + 10(.ovpn/remote 资产) + min(api_hosts, 8)

实战校准：60 分=YoloBase 系（可收割）；80+=AllConnected/大厂私有 SDK（需动态）；
<30=账号态门禁或死样本。**分数只决定优先级，不决定结论**——60 分组里也出了死池。
